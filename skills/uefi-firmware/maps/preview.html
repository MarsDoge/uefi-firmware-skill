展开步骤，查看动作与资料

01 定义问题

记录目标、现象、架构与已知条件；缺少关键输入时先收集，不猜测。

产出：明确目标与未知条件

参考：distillation-method.md

02 定位阶段与职责

定位启动阶段，跟踪生产者 → 接口 → 消费者；检查依赖何时可用。概念问题只定位相关阶段与接口。

产出：阶段、责任组件与依赖

参考：edk2-map.md · distillation-method.md

03 选择并收集依据

区分规范契约、edk2 实现、平台策略和工具行为；按问题读取适用规范、当前源码与配置、日志。

产出：可追溯依据及适用条件

参考：uefi-spec-map.md · debugging-map.md

04 提出判断或修复

解释类给出有边界的结论；排障类提出可检验假设；补丁类选择职责所属层的最小完整修复，检查兼容与失败路径。

产出：候选结论、假设或修复方案

参考：distillation-method.md · upstreaming.md

05 验证目标行为

按主张选择验证：规范与源码核对，或基线对照、目标架构构建、实际产物运行。检查相关失败路径；证据不足则返回定位，不把未测当作通过。

产出：验证结果、失败证据或明确缺口

参考：debugging-map.md · workflows.md

06 输出并沉淀

报告结论、依据、验证范围和缺口；可复用经验整理为规则 → 例子 → 边界，经审核后更新，不能把单次案例泛化为标准。

产出：可使用的答案与候选经验

参考：distillation-method.md · upstreaming.md

Agent 的阅读入口

读取 SKILL.md → 按问题选择参考 → 如需完整流程，读取 references/decision-flow.md。JSON 是维护与工具接口，不要求 Agent 每次读取。
